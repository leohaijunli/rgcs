# AF-01 — Same-process target facade checkpoint

- Date: 2026-10-25
- Authorization: owner standing implementation authorization; no repeated questions.
- Scope: explicit target identity and read-only facade over current native owners.
- Contract: [Runtime contracts](../architecture/runtime-contracts.md),
  [ADR-029](../adr/029-runtime-target-context.md).

## Delivered

1. `core::runtime` separates logical vehicle/session identity, promoted `LinkId`,
   transport generation and MAVLink route. Full-width counters use canonical
   decimal strings; opaque IDs use fallible OS-random issuance and bounded parsing.
2. `app-tauri/src/runtime_facade.rs` composes existing primary/dedicated services.
   It publishes lightweight target descriptors and returns exact target-bound
   read handles. A borrowed bench aliases the original worker/parameter service.
   Handles provide copied data, with no mutable AppState/cache or I/O shutdown API.
3. Target reads recheck identity before and after access. Replacement/reconnect
   invalidates old context; stale, unsupported or unverified sources have no
   available reference. Registry metadata is bounded to current supported roles.
4. Core telemetry clears aggregate values/ages on transport reopen. Parameter
   age records actual frame receive time; scoped reads exclude earlier-generation
   cache entries without replacing the shared cache.
5. Primary log requests pin the existing handle's discovered/configured node and
   source-filter responses. A nondefault 42/1 fixture ignores the foreign 43/1
   response and accepts only its own complete log list.
6. Rust-derived TS bindings are generated in canonical core bindings and the
   frontend mirror. `RuntimeVehicleId` is distinct from the existing route `VehicleId`.

The facade starts no transport/protocol/optional tool and sends no device command.
Existing effect adapters retain their single implementation; AF-02 introduces
owner-bound operations and the later tool slices migrate their consumers.
G1 includes AF-02; this checkpoint does not close G-ARCH or a physical-flight gate.

## Reproduction

From the workspace root:

```bash
cargo test -p maggcs-core --lib
cargo test -p maggcs-app --lib
TS_RS_EXPORT_DIR="$PWD/frontend/src/generated-types" cargo test -p maggcs-core --lib runtime
cargo clippy -p maggcs-core -p maggcs-app --all-targets -- -D warnings
cargo fmt --all -- --check
npm --prefix frontend run typecheck
cargo build --release -p maggcs-app
```

Inspect `runtime_facade::tests`, `main_link_service::tests`, the scoped-cache and
hub reopen tests and the nondefault log-node fixture for precise assertions.
Default tests exclude physical bench and opt-in external SITL/terrain cases.
Installed-FC reboot identity and electrical release retain their separate
ADR-028/AF-07 qualification requirements.
