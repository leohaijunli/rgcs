authorized continued small-slice implementation without repeated questions.

## 1. Native startup, idle resources and normal close

Profile: [AF-00 idle fixture](../../testdata/architecture/af00-idle/). Native
FC/base policies disabled/paused; legacy auto-connect OFF; no project, calibration,
terrain or recording loaded. XDG config/data/cache use a temporary profile.
The existing user profile and running external SITL were not used as test targets.

The collector attached to WebKit's loopback remote inspector and observed the
StartPage DOM. Timings include launch, inspector discovery/attachment and polling
(100 ms interval), so they are not an uninstrumented first-paint measurement.
Native `tauri://` Resource Timing returned zero byte sizes; that metric is
**unavailable**, not proof of zero script loading.

| Native run | StartPage observed ready (ms) | Idle process count | Idle summed RSS (KiB) | Idle summed threads | 5 s CPU sample, % of one core | Main native close → exit (ms) |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| First run in measured group | 1890 | 3 | 570104 | 105 | 7.6 | 71 |
| Warm process relaunch 1 | 754 | 3 | 635172 | 102 | 7.8 | 51 |
| Warm process relaunch 2 | 782 | 3 | 634388 | 103 | 10.0 | 30 |

All three native closes exited with code 0. No `maggcs-app`, WebKit web process or
WebKit network process remained after the measured group. The three idle processes
were the native host, one WebKit network process and one web renderer. Summed RSS
is not PSS/private memory and can double-count shared pages; OS threads are not
native service-task or DSP-worker counts. CPU comes from the second `top -b` sample
after a 5 s interval, summing this process tree only.

The binary/assets had been built and launched before this group. All native
launches therefore had warm OS file caches. A true post-boot/OS-cold measurement
has not been taken; no system cache flush was performed.

## 2. Native tool-open / cleanup measurements

Open commands were the existing `inspector_open`, `params_open`, `actuator_open`.
Ready means the tool root rendered, rather than a connected target/analysis job.
Inspector/Actuator used their explicit close command. Parameters and main were
closed through the compositor's native close request, exercising native hooks.
Cleanup observation ends when the inspected WebKit target disappears.

| Cycle | Inspector ready / cleanup (ms) | Parameters ready / cleanup (ms) | Motor Test ready / cleanup (ms) |
| --- | ---: | ---: | ---: |
| 1 | 732 / 19 | 612 / 519 | 2661 / 13 |
| 2 | 743 / 11 | 735 / 2509 | 980 / 13 |
| 3 | 726 / 8 | 581 / 518 | 521 / 8 |

Each open had four processes (one additional renderer). One second after closing
all three tools, process count returned to three and status remained passive:

| After cycle | Process count | Summed RSS (KiB) | Summed threads |
| --- | ---: | ---: | ---: |
| 1 | 3 | 495940 | 93 |
| 2 | 3 | 466120 | 93 |
| 3 | 3 | 470084 | 93 |

These three samples show no monotonic process/RSS growth for disconnected tool
cycling. They do not prove cleanup under active capture/DSP/FC output or leak-free
steady state for every workload. The Parameters renderer-disappearance outlier
is retained; no timing was rounded into a passing threshold.

Native windows were tiled by the current compositor. The DOM viewport was
1024×1056 while the first capture was 927 pixels wide; tool captures were tiled
927×521. These captures verify rendered native content, not AF-08's required
standalone-window sizes or layout qualification.

## 3. Browser cold / warm production-bundle loading

Served freshly built `frontend/dist` with Vite preview on a dedicated loopback
port. URL: `/?start&nomap`, viewport 1366×768. Each cold run used a new browser
context/HTTP cache. Warm means reloading that same context. Browser mock telemetry
is active; no native transport/backend exists in this measurement.

| Context | Cold DOM-ready / FCP (ms) | Warm DOM-ready / FCP (ms) | Cold JS heap used (bytes) | Warm JS heap used (bytes) | Web workers |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 784 / 808 | 161 / 168 | 10019716 | 15250348 | 0 |
| 2 | 293 / 300 | 192 / 200 | 9961236 | 15173788 | 0 |
| 3 | 323 / 328 | 122 / 132 | 9968696 | 15165028 | 0 |

- Each cold page fetched **4,961,198 decoded JS bytes**, **1,378,468 transfer
  bytes** across 16 scripts (transfer includes HTTP overhead/compression).
- `HeartbeatBanner-ZuiQBLP0.js`: **4,337,159 decoded bytes**, 1,171,589 transfer
  bytes. It contains the shared heavy workspace/Cesium dependency.
- `main-IWCu2I27.js`: 299,854 decoded bytes; `uPlot.min-C7ag3MJo.js`: 52,273.
- Warm Resource Timing reported zero body sizes and 300 transfer bytes per script
  for revalidation. The code was still present and executed; zero is not a lazy-
  loading or zero-code result.
- DOM nodes reported by CDP were 122 after cold load and 236 after reload. No
  forced GC was requested; retained prior document/heap values are not a leak
  diagnosis. All six loads had zero page errors and zero web workers.

The production build's mixed static/dynamic import warnings name `mission`,
`terrain`, `ui` and `polygon`. AF-03 should measure the actual entry dependency
graph and network requests rather than assuming `import()` already makes a
statically imported module lazy. Optional tool entries currently omit the heavy
workspace chunk and should retain that property.

## 5. Reproduction and artifacts

1. Build frontend then native as in README. Keep the commit, binary/profile and
   machine load in the evidence record; do not mix debug/native/browser timings.
2. Create a fresh temporary config/data/cache root. Copy the two
   [idle profile files](../../testdata/architecture/af00-idle/) to
   `config/io.maggcs.desktop/`. Point `XDG_CONFIG_HOME`, `XDG_DATA_HOME` and
   `XDG_CACHE_HOME` there; verify both native role policies and legacy timer OFF.
3. Native collector: the dated local script uses
   `WEBKIT_INSPECTOR_HTTP_SERVER=127.0.0.1:19223`, reads its `WebPage` target,
   routes `Runtime.evaluate` through `Target.sendMessageToTarget`, observes the
   StartPage/tool DOM and calls only the existing read/open/close commands.
   Sample the PID descendant tree with
   `ps -eo pid=,ppid=,rss=,nlwp=,times=,comm=` and
   `top -b -n 2 -d 5 -w 512 -p <owned-pids>`.
4. Repeat native tool sequence Inspector → Parameters → Motor Test three times.
   After all closes, wait one second and read the optional-state commands listed
   above. Issue main native close and wait for its actual exit code/PIDs.
5. Browser collector: use Vite preview, three new Playwright contexts, then one
   reload each; record `PerformanceNavigationTiming`, FCP, resource byte sizes,
   CDP `Performance.getMetrics`, worker count and page errors. DOM ready and FCP
   are separate observations. Capture a start-page image.
6. Run existing IPC fixtures against a Vite **dev** server (Parameters uses its
   dev store handle), with their URL and screenshot-directory arguments:

```bash
node frontend/scripts/check-inspector-connection.mjs http://localhost:5199/inspector.html /tmp/opencode/af00-browser/inspector
node frontend/scripts/check-params-connection.mjs http://localhost:5199/params.html /tmp/opencode/af00-browser/params
node frontend/scripts/check-motor-controls.mjs http://localhost:5199/actuator.html /tmp/opencode/af00-browser/motor
```
