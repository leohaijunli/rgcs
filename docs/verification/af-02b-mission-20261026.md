## Result

Upload, download, clear and set-current now use the existing single Mission
worker through owner/target/generation-bound transactions. IPC replies carry the
original `OperationRef` and a genuine terminal protocol result. Progress and
passive current observation are separately target-scoped; exact cancel/status
requires the native caller/session/operation.

Mission cancellation stops local retries only. Possibly changed FC state remains
uncertain and must be read back; no implicit clear, restore or set-current rollback
occurs. A confirmed local retirement releases the Runtime claim while core retains
same-generation ambiguous-reply quarantine. Reconnect creates a fresh session and
never replays old consequential intent.

The frontend captures the exact uploaded wire snapshot. An upload ACK records that
snapshot but never reports sync. A matching owned read-back is required. New edits,
local clear, old downloads, target replacement, hidden generation change and
wrong-owner/progress/current replies cannot overwrite or verify newer state.
Reconnect revokes the old baseline and reads back retained local plans.

| Scenario | Measured result |
| --- | --- |
| Four owned operations | Actual wire exchange reaches terminal ACK/current; exact operation owner/target/result returned |
| Invalid snapshot, foreign caller, stale prepared target | Zero Mission writes |
| Early upload ACK / out-of-range item request | Cannot report upload completion |
| Wrong Set current sequence | Passive observation only; exact requested sequence remains pending |
| Foreign source/destination/mission type | Ignored; only verified current peer advances protocol |

| Nullable parameters / bad altitude | NaN parameter sentinel round-trips as JSON null; non-finite altitude rejected |
| Concurrent owned or legacy exchange | Busy result; original operation remains authoritative |
| Owner cancellation after dispatch | Retry retirement within 1 s; uncertain FC state retained; zero rollback/retry |
| Idle/completed/old cancellation | Cannot cancel later work |
| Foreign cancellation / idle A close | B completes; primary transport and parameter cache remain alive |
| Owner native-close/reopen | Old work retires; captured old close cannot expire the reopened owner |
| Reconnect during active/prepared work | Old intent writes no replacement-generation frames; fresh operation succeeds |
| Full/closed event observer | Owned completion/cancellation remains responsive; drops are counted |
| Reboot/Motor interaction | Mission claim blocks reboot; borrowed Motor target blocks Mission admission |

## Manual verification

1. Create two waypoints, open Sync and upload. Confirm progress/counts and exact
   operation/generation render. Deliver upload ACK: the UI must show Checking,
   not In sync. Matching read-back then establishes both hashes.
2. Edit altitude while upload/read-back waits. Confirm the sent request remains
   unchanged and the edited plan remains visible, dirty and not falsely verified.
3. Cancel a dispatched upload. Confirm the exact operation/session is sent to
   cancel, the UI says local retries are retiring, and an uncertain result keeps
   the plan plus read-back warning.
4. Open More and click Clear FC mission once: no request. Confirm with the second
   click; denied ACK remains visible and does not clear the local baseline as
   success.
5. Start Download, edit a coordinate, then complete it. Confirm downloaded items
   are not applied and the newer edit/reason remains visible.
6. Replace the target during upload, issue a fresh upload, and deliver the old
   reply/progress first. The fresh operation remains active. Only its read-back
   establishes sync. Repeat with generation change not announced through link
   events; native reply revalidation must reject acceptance.
7. Select a waypoint and Set current. A different passive sequence may move
   observation but cannot complete the request. Exact sequence confirmation ends
   the operation and marks only the requested row current.
8. Stop/recover heartbeat. The old baseline/session clears; reconnect makes a
   fresh owned read-back and never replays upload/clear/current.
