## 1. 产品方向

**以独立操作 baseline 中的 UgCS Survey 功能为对齐目标，采用 RGCS 自身的、以测线为中心的工作区。** 目标包括航段组合、区域／走廊规划、载荷驱动网格、地形处理、动作、方案复制比较、执行与换电续测。

面向用户的层级是：**任务 → 航段 → 测线 → 编译后的航点**。日常操作以有业务含义的航段和测线为对象；具体航点仍然可以检查，并通过明确的覆盖规则编辑。

RGCS 的特色落在四个相互关联的能力上：

1. **测线优先的测量规划：** 主测线、联络线、校准线在生成、飞行航次和复盘之间保持身份一致。
2. **地图／剖面／Inspector 联动：** 选择测线或问题时，三个视图定位同一个对象。
3. **地形与任务版本可追溯：** 数据基准、DEM、计划高度、编译命令和飞控读回均对应明确输入。
4. **跨航次测量连续性：** 多块电池完成同一个 Survey 任务，明确处理未完成测线和补飞。

首批交付可以优先覆盖现有 `UavMag` 类型。摄影测量和 LiDAR 专属功能仍属于完整对齐目标，并在下方列为明确工作包。执行选项按目标机型能力提供：例如 DJI 的转弯名称或测距仪模式，需要有真实的 PX4 执行契约，才能显示为“支持”。

### 4.1 任务上下文与航段大纲

- 保留五阶段模型，空间允许时直接显示阶段，窄屏保留紧凑 Workflow 选择器；旁边显示当前任务和草稿／飞控版本。
- 地图左边增加可折叠大纲，按飞行顺序列出有类型的航段，可展开到测线及编译后的航点。
- 航段操作包括前／后插入、复制、移动、适用时反向、在编辑器隐藏、从任务禁用、删除。**隐藏**与**禁用**是不同操作。
- 插入校准航段后保留前后测区；编辑端点不清空无关 pattern 参数。
- 从选中测线或高级入口查看原始航点；生成后仍停留在 Survey 编辑上下文。
- 新建空任务复用 Area／Pattern 卡片。引导式创建与后续对象编辑共用同一个持久草稿。

### 4.2 上下文 Inspector

Inspector 展示当前选中对象的内容。

| 选择对象 | 主要字段／操作 |
| --- | --- |
| 任务 | 机型 profile、测量配方、默认高度策略、结束策略、版本／方案操作 |
| 测区 | 边界来源、顶点、平移／旋转、面积、数据覆盖、几何有效性 |
| Survey 航段 | 工具类型、高度／GSD、间距／重叠率、速度、方向、入口、适用时的双网格 |
| 测线 | 稳定 ID、角色、长度、方向、继承值、显式覆盖值、启用／反向 |
| 接近／转弯／返程 | 几何、高度／净空策略、速度、地形覆盖、适用机型约束 |
| 航点 | 坐标、带基准高度、命令参数、锁定、来源测线／航段、覆盖状态 |
| 问题 | 实测／计算值、要求限值、数据来源、受影响区间、可修正字段 |

使用 **Basic／Advanced／Actions／Checks** 四个功能分组：

- **基础：** 当前工具最常修改的参数。
- **高级：** 引入／引出、overshoot 速度、转弯、平滑、容差、联络线及工具专属参数。
- **动作：** 有序的载荷、航向、等待动作，以及执行范围。
- **检查：** 绑定当前计算版本的结构化结果。

磁测配方显示线间距、Tie 和校准参数；摄影配方显示 GSD／重叠率；LiDAR 配方显示幅宽／重叠要求。航段组合和操作方式共用。

### 4.3 地图交互

1. 选中测区后，显示平移／旋转、顶点、测线方向和入口控制柄。
2. 拖动方向箭头或输入准确角度；保留手动锁定的方向。
3. 移动起飞点，查看推荐入口；允许手工换入口及反转遍历方向。
4. 点击测线，以稳定 ID 同步选中大纲、Inspector 和剖面。
5. 点击问题标记，定位到具体测线、沿线区间和相关参数。
6. 航点按需展开；地形加密产生很多点时，测线身份依然清晰。
7. 复用现有语义颜色：主测线用 accent、联络线用现有黄色系、校准线用 mag 色、转场用弱化虚线。同时使用标签和线型，问题另带独立标记。

### 4.4 统一剖面工作面

扩展 `ProfileDrawer`，支持整任务、当前测线、实时三种视图，复用现有 uPlot 和地形／监控输出。

- 显示 DTM、DSM、实际配置的净空底线、目标 AGL 带、设计曲线和编译轨迹；实际飞行曲线只叠加到其对应基线上。
- 横向航段条标识起飞／接近／S01／转弯／S02／返回／降落，点击后同步选中地图对象。
- 联动游标显示测线 ID、沿线距离、带基准高度、AGL、净空及数据是否可用。
- 对**全部相关航段**采样地形；不能将端点地面值插值当作中间位置的真实地形采样。
- 数据缺口明确显示未知；高度带、净空底线与 Inspector 使用同一计算结果，没有独立显示默认值。
- 显示 DEM 身份、基准、分辨率／采集日期、结果是否属于当前草稿。

### 4.5 摘要与计算反馈

扩展已有 `PlanSummary`，显示任务面积、测量／转场长度、各类测线数量、完整任务项数、ETA、适用的载荷采集量和可定位问题。

有效参数变化后采用已有的防抖计算思路；计算期间将旧结果标为过期，保留主动 Recalculate。新结果只有在**完整输入版本**仍匹配时才能应用。上传期间编辑会形成新草稿，已发送快照保留自身身份。

分别表达三种状态：

- 计算：编辑中／计算中／完整／部分／失败。
- 同步：未发送／上传中／读回中／已核对／不一致。
- 执行：就绪／执行中／中断／完成，由后续会话模块提供。

### 4.6 响应式与现场布局

- 宽屏桌面显示大纲和可调节的 320–360 px Plan Inspector。
- 1366×768 使用紧凑大纲及约 320 px Inspector，大纲可独立折叠，保留地图编辑空间。
- 1024×640 使用抽屉／弹出式大纲，保持一个主要编辑面；剖面可折叠、调整高度。
- 复用现有亮色、暗色、夜红主题；Field 密度将主要触控目标增至至少 44 px，参数单位和标签保持可见。
- 坐标、高度、限值、哈希使用等宽字体；重要信息不依赖纯颜色或 hover。
- 保存面板尺寸与折叠选择，普通选线操作不自动展开所有面板。

### 4.8 两层顶部导航提案

**任务栏，约 40–44 px：**

`Prepare · Plan · Preflight · Fly · Review | Survey 选择 · 版本状态 · Resources · 当前阶段主操作`

- ≥1440 px 显示五个简短阶段标签和 Preflight 徽标。
- 1100–1439 px 先缩短上下文文字、移除次要快捷入口；实际空间不足时使用现有阶段选择器。
- <1100 px 使用 `Plan · 2/5 ▾`、截断的任务名和阶段主操作。电量、链路／模式、告警、Hold／RTL 不需要打开 More 才能找到。
- 收缩顺序：可选工具快捷键 → 长项目／任务名 → 展开的阶段导航 → 次要元数据；关键飞行状态优先。
- 阶段可以自由切换。点击 **Fly** 只切换视图；**Start mission、Hold、RTL** 是真实命令，沿用已有可用性、确认和 ACK 反馈。

准备状态单独显示，例如 Prepare“数据就绪”、Plan“已计算”、Preflight“2 项问题”、Fly“空闲／执行中”、Review“有会话可查看”。不能通过用户是否访问过某阶段来推断完成情况。

### 4.9 菜单结构

采用一个清晰的应用菜单、紧邻任务名的任务菜单，以及大纲／Inspector 中的对象操作。借鉴 UgCS 的任务、profile 和资源概念，复用 RGCS 现有工具窗口。

```text
应用菜单
  Project          新建／打开／最近项目／导入／导出
  Resources        地图／高程源／机型 profile
                   载荷 profile／Survey 配方
  Tools            参数／Signal Inspector／Motor test／Flight logs
                   导出诊断
  View             大纲／Inspector／剖面／Field mode／主题
  Settings         连接／设备／应用偏好
  Help             快捷键／文档／About

Survey 菜单（任务名旁）
  新建任务／重命名／复制／保存为配方
  导入边界／导入任务／导出任务
  比较版本／飞行航次／归档任务

  前方插入／后方插入／复制／调整顺序
```

### 4.10 各阶段主操作

| 阶段 | 主操作 | 辅助操作 |
| --- | --- | --- |
| Prepare | 准备测区数据 | 导入边界、选择资源／profile、检查覆盖 |
| Plan | 审查并上传当前计算结果 | 重新计算、比较版本、导出 |
| Preflight | 通过机型适配器启动已核对任务 | 打开定位问题、检查飞控任务 |
| Fly | 显示活动航次／测线和命令反馈 | 现有 Hold／RTL／Commands 控制；SW-12 启用后提供续测 |
| Review | 打开／导出会话报告 | 比较计划与实际；SW-13 启用后选择补飞测线 |

实际飞行期间，即使操作员打开 Plan 或 Review，任务栏仍标明正在执行的快照。草稿修改、预览图和飞控活动任务具有独立且明确的身份。

### 4.11 高程源入口与 UgCS 默认数据库

当前 UgCS 官方手册把内置高程源列为 **SRTM**，水平坐标基准为 **WGS84／EPSG:4326**，垂直基准为 **EGM96**；同时支持自定义 DEM／DTM／DSM 及源数据优先级。引用页面没有给出统一的内置分辨率，因此 UI 应显示实际所选数据源的元数据，不能默认它是 1 m。导入和垂直基准细节见操作 baseline 的 D05。

RGCS 的 Resources → Elevation 抽屉应逐源显示：

`名称／来源 · DTM／DSM 角色 · 分辨率 · 采集日期 · 水平 CRS · 垂直基准 · 覆盖 · 优先级 · 离线可用性`

任务栏标签可显示 `Terrain · HRDEM 1 m · Ready` 或 `Terrain · Coverage missing`。展开后显示输入基准，以及到任务工作基准的已核对转换。影像与高程放在明确命名的不同资源页，避免更换底图让人误以为规划高程也已更换。

### 4.12 工程实践与美学规范

目标是安静、准确的工程工作台。视觉层级跟随操作员的决策顺序：**任务 → 当前对象 → 输入参数 → 计算证据 → 执行状态**。

| 原则 | 具体规范 |
| --- | --- |
| 控制位置稳定 | 飞行命令和重要健康状态固定；打开菜单、切换阶段不移动 Hold／RTL。 |
| 作用域明确 | 标题显示当前任务／航段／测线；命令使用“动词＋对象”，例如导出任务、删除航段。 |
| 数值表达准确 | 数值、单位、基准／参考、来源能够一起查看；零值、Unknown、Stale、Not applicable 明确区分。 |
| 克制用色 | 工作底色保持中性；accent 用于选中和主操作，严重性颜色表达真实状态；测线同时依靠 ID 和线型区分。 |
| 密度统一 | 使用 4／8／12／16 px 间距节奏，分区边缘对齐；普通行／控件约 32 px，Field 主触控目标至少 44 px。 |
| 字体层级清楚 | 主标签约 14 px，辅助标签一般不小于 12 px，数值列用等宽字体；单位和关键命令文字不截断。 |
| 容器低干扰 | 使用共用面板和细分隔线，减少卡片层层套卡片；圆角尺度统一，阴影主要标识浮层。 |
| 地图是主工作面 | 必要时降低底图对比，突出选中测线和问题区间；航点标签按需显示。 |
| 主操作明确 | 当前阶段只突出一个主操作；次要命令放相邻位置或正确作用域的菜单。 |
| 修改可追溯 | 显示继承／覆盖值、计算时间／版本，以及重要修改的简洁前后对比。 |

复用仓库现有设计 token，不另建一套视觉主题。示意图使用当前暗色系；亮色／Field 和夜红主题保持相同的信息层级与对比关系。

### 4.13 用实际工程过程验证布局

1. **室内准备：** 导入 AOI → 选择资源／配方 → 设置方向与间距 → 比较方案 → 检查完整地形／约束结果。
2. **到达现场：** 识别实际飞行器／Home → 调整起降点 → 重算接近／返回 → 检查高度和时长变化 → 上传／读回。
3. **处理问题：** 点击问题数量 → 地图和剖面定位区间 → 修改相关参数 → 得到新计算版本。
4. **换电续测：** 确认未完成测线 → 选择重启／接入策略 → 查看重复与剩余覆盖 → 执行新航次。
5. **复盘：** 选实际会话 → 将冻结计划与实际数据比较 → 查看来源及测线结果 → 导出或准备补飞。

[导航示意图](ugcs-survey-navigation-concept.svg) 将不同菜单作为独立示例状态展示，不表示实际使用时需要同时打开多个弹窗。

## 5. RGCS 的特色工作流

### 5.1 测量配方

将已有预设扩展成带版本的任务配方：机型／载荷关联、几何默认值、高度策略、Tie、校准、动作、返回行为。明确区分配方默认值与任务／测线覆盖值。

将已有 **Align ∥ B** 提升为磁测配方中的明确操作，同时提供准确手工方向和长边辅助。方向比较显示转场距离、转弯次数、点数和 ETA 的变化，保留操作员规定的测线方向。

### 5.2 全航程预览与采集角色

显式组合完整飞行：

`起飞 → 接近 → 校准 → 引入 → 主测线／联络线 → 转弯 → 返回 → 降落`

各航段按角色接受地形及约束处理。计划返程与飞控紧急 RTL 分别记录。对连续磁采集，转场数据仍可记录，但测量分类明确；相机触发开关属于载荷策略，不默认套用于全部传感器。

### 5.3 按测线理解换电续测

续测面板保留 baseline 选项，并增加测量语境：

```text
继续 Survey —— 下一航次
已完成：S01–S08       中断：S09，234 / 610 m

续测来源：中断位置／选定测线／选定航点／任务起点
测线策略：继续剩余部分／重飞中断测线
进入方式：经过计划首点／明确的直接接入或重新进入路径

预览：起飞 → 已检查接近路径 → 引入段 → 续测 → 返回
报告：重复距离、剩余覆盖、ETA 与返程余量
上下文：新飞行器／Home／高度锚点、任务版本、已上传版本
```

完成状态来自执行台账及后续 QC，不能只靠一个 `MISSION_CURRENT` 数字。重复／乱序遥测、改点、断线重连、飞行器重启，都应保持真实进度。补飞作为同一任务的新 Session，保留来源测线身份。

### 5.4 可复现复盘

复用 recorder／project／archive，将每次实际执行快照与任务、来源测线、DEM／基准链、飞控参数、动作和未完成／重复区间关联。后续航线 QC 复用已有 drape monitor 的偏差计算。

完整会话／QC 有现有路线图依赖，见第 8 节。

## 6. 模型与代码落点

### 6.1 持久化模型

沿用 Project → Survey → Session 组织，扩展 Survey 的规划内容，保存有序语义航段和版本。以下是实施前需要评审的契约：

| 契约 | 职责 |
| --- | --- |
| `SurveyDraft` | 持久几何、配方、机型／载荷引用、有序航段和显式覆盖值 |
| `SurveySegment`／`LegRole` | 稳定航段身份及起飞／转场／主测／Tie／校准／转弯／返回／降落角色 |
| `LineId`／来源映射 | 与 MAVLink 序号分离的稳定测线身份 |
| `CalculationRevision` | 几何、参数／动作、DEM／基准网格版本及相关机型能力的指纹 |
| `MissionPreview` | 完整路线、采样剖面、摘要、完整／部分状态和可定位问题 |
| `CompiledMissionSnapshot` | 不可变协议任务项、来源映射、目标身份、编译／高度锚点上下文和哈希 |
| `PlanSelection` | 地图、大纲、Inspector、剖面共用的航段／测线／航点／区间选择 |
| `SurveyExecution` | 后续用于中断／完成／补飞的执行台账，依赖推迟中的 M1 |

这些是设计契约，不是声称已经存在的新类型。core 绝对高度继续使用 `height::Height`。垂直基准转换、估计器锚点补偿、相对 Home 编码分别表达并记录输入。

### 6.2 计算与执行链

```text
SurveyDraft + 资源 + 机型能力
  → 生成语义航段／测线
  → 组合接近、转弯、返回和起终点
  → 对完整路线采样／求解／简化地形轨迹
  → 校验几何、动作、限值和数据覆盖
  → MissionPreview + CompiledMissionSnapshot
  → 显示／导出／上传明确版本的结果
  → 用已发送快照核对飞控读回
  → 将执行事件映射回来源测线
```

路线、高度、约束等数值权威仍在 Rust；React store 负责草稿交互及结果展示，统一各视图对地形与准备状态的解释。

## 9. 验收方案

1. **功能对齐：** 执行独立 baseline 的 11 组对照场景，记录各 BL 能力、目标 profile、结果和剩余差异。
2. **高度一致性：** 控制点转换、等价基准夹具、有／无 anchor、导入／导出、最终协议 payload 对照。
3. **几何：** 凹多边形、多条同类测线、多 Survey 航段、校准插入、陡峭进出场、缺失地形。
4. **并发：** 快速编辑、DEM 切换、计算延迟、上传中编辑、读回丢失、目标切换、断线重连。
5. **飞控执行：** SITL 验证速度、动作、模式切换、爬升／下降、点数上限和续测进入；对比实际轨迹，不假设等于画出的折线。
6. **UI：** 1920×1080、1366×768、1024×640；暗色／亮色／Field；键盘和语义撤销；截图／手工验证联动选择、菜单焦点／Escape、常驻电量／Hold／RTL，以及切换阶段不停止监控。
7. **性能目标：** 在声明的 1,000 条来源测线夹具上测量选线联动 p95 ≤100 ms，生成耗时单独记录；这是目标，不是当前实测结果。
8. **后续连续性／QC：** 遥测重复、跳点、乱序；换电／Home／anchor 变化；中途续线；复现会话报告。

## 12. Flight Plan、Drape、Execution、Monitor 模块拆分

### 12.1 推荐分解

以四个主领域模块为核心，配合共享资源／编译服务。这里首先是逻辑边界，每个模块不必各占一个进程或顶层菜单。

| 模块 | 拥有的职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| **Flight Plan** | 任务草稿、语义航段、稳定 LineId、图案生成、入口／顺序、方案变体、覆盖值和编辑历史 | 测量配方、AOI、机型／载荷规划能力、用户编辑 | 带版本的路线意图及水平／语义几何 |
| **Drape** | 地形采样、带基准高程设计、净空包络、爬升／下降整形、简化证据、不可行报告 | 路线几何／角色、高度意图、DTM／DSM、约束、输入版本 | 高度剖面、贴地几何、覆盖／缺口／约束报告、来源信息 |
| **Mission Execution** | 绑定目标的上传／读回、活动不可变任务、启动／Hold／返回意图、执行会话及后续续测协调 | 已检查编译快照、已验证目标、实时准入事实、明确操作意图 | 上传／执行状态、实际执行基线、协议结果、会话事件 |
| **Flight Monitor** | 计划／实际匹配、进度观察、横向／高度／速度偏差、数据新鲜度、告警 | 冻结执行基线、带时间戳遥测、相关地形参考 | 实时指标、带 LineId／区间的事件、偏差和监控记录 |

**共享服务：**

- **Terrain Resources／Height：** 数据源选择、缓存、DTM／DSM、基准／网格版本与转换。SRTM／HRDEM／CDEM／Copernicus 属于这一层的数据源问题。
- **Mission Compiler／Planning Validator：** 统一命令／动作编码、高度 frame 转换、seq 与来源映射、完整任务项上限及静态可行性，输出 `CompiledMissionSnapshot`。
- **Vehicle Runtime／Safety：** 连接所有权、当前能力、操作仲裁、实时准入和命令发送。
- **Project／Recorder／Archive：** 草稿、快照、会话、来源及输出持久化。
- **Survey QC／Review：** 后续质量规则和补飞决策，基于监控／记录数据并沿用现有推迟依赖。

```text
                                                      |
                                              建议补飞测线
                                                      |
                                           明确创建新规划草稿

底层共享：类型化路线契约、Terrain／Height、机型能力、Vehicle Runtime、
Project／Recorder；各模块调用由应用用例协调，不通过 UI store 相互串联。
```

- Flight Plan 不订阅实时监控来自动改写草稿。
- Drape 返回结果，不修改编辑器、不访问 UI store、不打开串口、不上传任务、不发速度命令。
- 命令编码只有一个所有者：逐步将现有 `drape_compile` 中产生协议命令的部分收敛到统一 Compiler，保留已验证的高度简化算法。
- Mission Execution 持有活动快照；即使 Flight Plan 正在编辑新版本，Flight Monitor 仍观察已执行快照。
- Flight Monitor 产生观察／告警；控制响应必须经明确的 Execution／Runtime 策略。
- QC 用来源 ID 建议补飞；生成新任务版本属于明确的规划操作，避免形成自动控制的循环依赖。

### 12.3 实施前评审的接口草图

公共契约保持小而带版本，语义合适时复用 `Height`、`GeoPoint`、现有 line／profile／mission 类型：

```text
FlightPlan.generate(SurveyDraft, PlanningContext)
  → RouteIntent / PlanError

Drape.solve(RouteIntent, DrapeSpec, TerrainSnapshot)
  → DrapedRoute + DrapeReport / DrapeError

MissionCompiler.compile(RouteIntent or DrapedRoute, CompileContext)
  → CompiledMissionSnapshot + ValidationReport / CompileError

MissionExecution.upload(CompiledMissionSnapshot, TargetRef)
  → TransferId；随后产生确认／读回事件

MissionExecution.start(VerifiedSnapshotRef, OperationContext)
  → ExecutionId / ExecutionError

FlightMonitor.attach(ExecutionBaseline)
FlightMonitor.observe(TimestampedTelemetry)
  → MonitorUpdate {line_id, span, metrics, freshness, events}
```

每个结果携带输入版本。地形结果标识数据源／网格版本及基准；编译结果将协议 seq 映射回稳定航段／测线 ID；执行基线还记录目标／generation 和上传时的高度 anchor。UI 意图不等于执行确认。

错误按边界归属：无效 AOI／pattern 属于 Flight Plan；地形／基准缺失和不可行几何属于 Drape；动作／frame／点数问题属于 Compiler；目标错误、资源冲突、传输失败、结果不确定属于 Execution。遥测过期／缺失属于 Monitor 的显式状态，不是“测得零偏差”。

### 12.4 UI 与生命周期映射

| 工作区 | UI 聚合的模块 |
| --- | --- |
| Prepare | Terrain Resources、profile／机型能力、数据就绪状态 |
| Plan | Flight Plan + Drape + Compiler 预览，共用地图／大纲／剖面 |
| Preflight | 规划验证结果 + 实时 Runtime／Safety + 已核对执行快照 |
| Fly | Execution 状态 + Flight Monitor；草稿仍可独立编辑 |
| Review | 冻结快照、已记录监控数据、后续 QC 和补飞规划 |

Drape 主要表现为 Plan 的能力和剖面视图；顶层仍按作业阶段组织。Flight Monitor 通过共享 Runtime 同时服务 Fly 工作区和只读工具消费者。

Monitor／Recorder 生命周期跟随活动执行上下文，不跟随 React 组件挂载。Drape 重算是可取消后台 job：关闭面板只解除该视图；输入被新版本替代时，根据 revision 取消或丢弃旧 job。

### 12.6 独立验证与扩展

1. Flight Plan 在没有飞行器连接时也能生成可复现任务。
2. Drape 用合成 DTM／DSM 测试，不需要 Tauri、WebView 或 MAVLink I/O。
3. Compiler 解码真实产出命令，核对高度、动作、点数和来源映射不变量。
4. Execution 用假 FC／SITL 覆盖传输中断和错误目标。
5. Monitor 回放冻结基线和遥测；修改草稿不能改变结果。
6. 新增地形源只扩展 Terrain Resources，不改变 Monitor UI 契约。
7. 新增图案生成器扩展 Flight Plan；新增飞控适配器扩展 Execution／capabilities。
8. 新 QC 规则消费稳定观察值和来源 ID，不获得飞行链路所有权。

该拆分支持离线规划、可回放监控、独立工具 UI 和后续进程部署，仍与整个方案一样暂停实施，等待 review。

### 12.7 按需加载，同时保持飞行鲁棒性

使用规划时才加载 Flight Plan 工作区，请求地形／剖面计算时才启动 Drape。必需的监控／记录服务由执行生命周期启动，在飞行需要期间 pin 其基线和资源。轻量 Runtime 协调及已配置连接角色独立于 UI 显隐。

采用有界 job、单次初始化、按 revision 取消、明确的空闲回收。详细加载／保留矩阵和验收见[工具架构第 11 节](tool-module-architecture-plan.zh-CN.md#11-按需加载效率与鲁棒生命周期)。这样可以按模块扩展、提高启动效率，同时避免关面板导致活动操作被卸载。
